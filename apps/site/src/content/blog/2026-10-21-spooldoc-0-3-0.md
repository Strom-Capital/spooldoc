Spooldoc 0.3.0 is out. A job can now make Word and Excel files as well as
PDF and HTML, and write them to a folder in the IFS, where programs on the
IBM i can pick them up. Every document is rendered by
[Carbone](https://carbone.io). This release has breaking changes, so read
[Upgrading](#upgrading) before you pull it.

## What changed

**Word and Excel templates.** Next to HTML, a template can be a Word
document with tags in its text, or an Excel workbook with tags in its
cells. A Word template makes DOCX files, PDFs or both. An Excel template
makes XLSX files, PDFs or both, by default one of the whole spooled file
with a row per line. A job can have several templates, so one spooled file
can become a PDF for the customer and a workbook for the office in the
same run. [Templates](/docs/templates/) has the tags.

**The agent designs Word and Excel templates.** The chat beside the job
builder is now called the agent. It asks which kind of template you want,
then designs a new Word or Excel template from your prompt and the sample
spooled file, or makes a new version of one you uploaded. Settings and the
agent panel show how many tokens it used. Masking is now a setting, and it
is off on a new install.

**IFS destination.** A job can write its files to a folder in the IFS on
the server it reads from. You choose what happens when a file with the
same name is already there: replace it, add a number, or fail the run. A
file is written under a temporary name first and only then takes its name,
so a program watching the folder never sees half a file, and no file is
lost when a step fails. [IFS folder](/docs/destinations/#ifs-folder) has
the details.

<p align="center"><img data-theme-image="light" src="/docs/assets/destination-ifs-light.png" alt="The New IFS destination dialog filled in: a name, a folder, Add a number when a file with the same name exists, and Keep a copy in Spooldoc on" width="900" height="563"><img data-theme-image="dark" src="/docs/assets/destination-ifs-dark.png" alt="The New IFS destination dialog filled in: a name, a folder, Add a number when a file with the same name exists, and Keep a copy in Spooldoc on" width="900" height="563"></p>

**Shorter tags, and page groups.** What 0.2.0 called a document is now a
page group: the pages of a spooled file that become one document.
Templates use Carbone tags, such as `{d.pg.invoiceNo}` for a field of the
page group and `{d.pgs}` for all of them.

**Connections that come back.** When the connection to the IBM i drops,
Spooldoc reconnects, and the Servers page shows the connection's state.
New spooled files wait while Carbone does not work, and are rendered when
it does.

**Finding your way.** The sidebar is grouped, with a Profile page
and a menu on phones. Nested pages have breadcrumbs. The Queues and
Servers pages show the jobs of each queue and server, and each queue shows
how many files are ready and held. The job builder has Back and Next
between steps. The docs are in the app at `/docs`, and the Support group
links to them, to Discussions and to the issues.

All changes are in the
[release notes](https://github.com/Strom-Capital/spooldoc/releases/tag/v0.3.0).

## Upgrading

Take a `pg_dump`, then pull `ghcr.io/strom-capital/spooldoc:0.3.0` and
start it. The server applies the new migrations, and every job and version
from 0.2.0 opens again, its template now the job's first template. Two
things need you:

- **Run Carbone.** Add the `carbone` service from
  [compose.yaml](https://github.com/Strom-Capital/spooldoc/blob/v0.3.0/compose.yaml).
  Then copy the public key from Settings, under Rendering, into
  `CARBONE_AUTHENTICATION_PUBLIC_KEY` in `.env`, run
  `docker compose up -d carbone` and click **Check** again.
  [Carbone](/docs/carbone/) has the steps.
- **Rewrite Nunjucks tags.** Templates and file name patterns written for
  0.2.0 use Nunjucks, such as `{{ doc.invoiceNo }}`. Rewrite them as
  Carbone tags, such as `{d.pg.invoiceNo}`. Each job's Template tab lists
  what is left, and the definition check names a file name pattern that
  still has it. Until then, a run of the job fails with the same message.
  Save the job as a new version once both are rewritten.

In XML definitions, `xml.document:` is now `xml.pageGroup:`. The upgrade
renames it in the definitions saved in Spooldoc. Rename it in any copies
you keep elsewhere. [From 0.2.0](/docs/deployment/#from-020) has the
steps.
